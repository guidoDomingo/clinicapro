🏗️ 1. Arquitectura General del Sistema

Patrón MVC (Model-View-Controller)

El módulo de consultas sigue estrictamente el patrón MVC con las siguientes capas:

Capa Responsabilidad Archivos Principales
View (Vista) Interfaz de usuario, formularios HTML consultas.php, frmConsultaGeneral.php, frmConsultaAnteojos.php
Controller (Controlador) Lógica de negocio, validaciones consultas.controller.php
Model (Modelo) Acceso a datos, consultas SQL consultas.model.php, conexion.php
AJAX (Comunicación) Comunicación asíncrona consultas.ajax.php, guardar-consulta-*.php
JavaScript (Frontend) Interactividad, validaciones cliente consultas.js, cargar_datos.js

🔑 Características Clave del Sistema:

  • Formularios Dinámicos: Cambio entre tipos sin recargar página
  • Preformatos Contextuales: Plantillas específicas por tipo de formulario
  • Gestión de Archivos: Subida y asociación de documentos
  • Integración PDF/WhatsApp: Generación y envío automático
  • Histórico de Consultas: Timeline y reutilización de datos

🔄 4. Flujo de Cambio de Formularios

🎯 Proceso de Cambio de Tipo de Formulario

1️⃣ Detección de Cambio

El usuario selecciona un tipo diferente en el selector de formularios

function cambiarFormulario(formType) { // Verificar si hay un paciente seleccionado const idPaciente = document.getElementById('idPersona') ? document.getElementById('idPersona').value : ''; // Construir nueva URL let nuevaUrl = 'index.php?ruta=consultas&form_type=' + formType; // Preservar paciente si existe if (idPaciente) { nuevaUrl += '&paciente_id=' + idPaciente; } // Redirigir para limpiar estado window.location.href = nuevaUrl; }

2️⃣ Carga del Formulario

El servidor PHP determina qué formulario cargar basado en el parámetro

// En consultas.php $form_type = isset($_GET['form_type']) ? $_GET['form_type'] : 'general'; $form_files = [ 'general' => "view/inc/consulta_forms/frmConsultaGeneral.php", 'anteojos' => "view/inc/consulta_forms/frmConsultaAnteojos.php", ]; $form_file = isset($form_files[$form_type]) ? $form_files[$form_type] : $form_files['general']; include $form_file;

3️⃣ Inicialización JavaScript

Se ejecutan los scripts específicos para el tipo de formulario

document.addEventListener('DOMContentLoaded', function() { const urlParams = new URLSearchParams(window.location.search); const formType = urlParams.get('form_type'); console.log("Tipo de formulario detectado:", formType); // Cargar preformatos específicos del tipo cargarPreformatosEspecificos(formType); // Configurar comportamientos específicos configurarFormularioEspecifico(formType); });

4️⃣ Carga de Preformatos

Se cargan plantillas y motivos específicos del tipo de formulario

function cargarPreformatosEspecificos(tipoFormulario) { // Cargar preformatos de consulta $.ajax({ url: 'ajax/preformatos.ajax.php', data: { tipo: 'consulta', tipo_formulario: tipoFormulario }, success: function(data) { llenarSelect('#formatoConsulta', data); } }); // Cargar preformatos de receta // Similar para motivos comunes... }

⚠️ Consideraciones Importantes:

  • Estado de Formulario: El cambio limpia datos no guardados
  • Preservación de Paciente: Se mantiene el paciente seleccionado
  • URLs Limpias: No se incluye id_consulta para evitar cargas no deseadas
  • Validación de Tipo: Fallback a 'general' si tipo no válido

• Para edición de consultas existentes

• Gestión de archivos asociados a consultas
• Subida, listado, eliminación de documentos
POST ajax/preformatos.ajax.php
• Obtención de plantillas contextuales
• Filtrado por tipo y tipo_formulario

🎭 8. Casos de Uso Principales

🔄 Caso de Uso 1: Cambiar Tipo de Formulario

Actor: Médico/Usuario del sistema
Precondición: Usuario en página de consultas
Flujo Principal:
  1. Usuario selecciona tipo de formulario desde dropdown
  2. Sistema ejecuta función cambiarFormulario()
  3. Se preserva ID de paciente si existe
  4. Se construye nueva URL con parámetros
  5. Página se recarga con formulario específico
  6. Sistema carga preformatos contextuales
  7. Interfaz se adapta al nuevo tipo
Postcondición: Formulario cambiado, estado limpio, paciente preservado

👤 Caso de Uso 2: Crear Consulta de Anteojos

Actor: Oftalmólogo
Precondición: Formulario tipo 'anteojos' cargado
Flujo Principal:
  1. Médico busca y selecciona paciente
  2. Sistema carga datos del paciente en formulario
  3. Médico completa campos específicos de anteojos (esferas, cilindros, etc.)
  4. Médico agrega descripción y receta
  5. Sistema valida campos obligatorios
  6. Se ejecuta guardarConsultaAnteojos()
  7. Backend guarda en tabla consultas + consulta_anteojos
  8. Sistema retorna ID de consulta creada
  9. Se habilitan opciones de PDF/WhatsApp
Postcondición: Consulta guardada, archivos asociables, PDF generado

📋 Caso de Uso 3: Editar Consulta Existente

Actor: Médico/Administrador
Precondición: Consulta existe en base de datos
Flujo Principal:
  1. Usuario accede con URL: consultas.php?id_consulta=X
  2. Sistema obtiene tipo de formulario de la consulta
  3. Si tipo actual ≠ tipo consulta → redirección automática
  4. Sistema carga datos del paciente asociado
  5. Se recuperan datos específicos (general o anteojos)
  6. Formulario se llena con datos existentes
  7. Usuario modifica campos necesarios
  8. Al guardar, se ejecuta actualización (no inserción)
  9. Datos se actualizan en tablas correspondientes
Postcondición: Consulta actualizada, historial preservado

📁 Caso de Uso 4: Gestión de Archivos

Actor: Personal médico
Precondición: Consulta creada o en edición
Flujo Principal:
  1. Usuario arrastra archivos a zona de drop o selecciona
  2. Sistema valida tipos y tamaños
  3. Se muestra preview de archivos seleccionados
  4. Usuario hace clic en "Subir Archivos"
  5. Sistema verifica paciente e ID de consulta
  6. Archivos se guardan en servidor
  7. Metadatos se almacenan en reserva_archivos
  8. Interfaz se actualiza con archivos subidos
  9. Opciones de descarga/eliminación disponibles
Postcondición: Archivos asociados a consulta, accesibles en historial

⚠️ Consideraciones Especiales:

  • Concurrencia: Prevención de guardados simultáneos
  • Validaciones: Cliente y servidor para datos críticos
  • Rollback: Transacciones para operaciones complejas
  • Logging: Trazabilidad completa de operaciones
  • Seguridad: Validación de permisos y sanitización
